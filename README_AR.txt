Cashier Pro — نسخة إصلاح توافق قاعدة البيانات

المحتويات:
- worker.js: نسخة Worker معدلة لتتحمل اختلاف أسماء أعمدة الإعدادات وسجل العمليات.
- public/index.html: واجهة Cashier Pro.
- schema.sql: مخطط قاعدة بيانات للتثبيت الجديد فقط.
- wrangler.toml: إعداد Worker وربط D1 وملفات الواجهة.

مهم جدًا للمشروع الموجود بالفعل:
1) لا تحذف قاعدة cashier-pro-db ولا تنفذ schema.sql فوق قاعدة البيانات الحالية.
2) احتفظ بنسخة من worker.js الحالي قبل الاستبدال.
3) ارفع الملفات الموجودة في هذا المجلد إلى مستودع cashier-pro مع الحفاظ على المجلد public.
4) تأكد أن Cloudflare Worker ما زال مربوطًا بقاعدة D1 باسم DB وبـ Assets باسم ASSETS.
5) انشر باستخدام: npx wrangler deploy

التغييرات الأساسية:
- تسجيل سجل العمليات أصبح مرنًا: يستخدم الأعمدة الموجودة فعليًا في audit_logs، وأي فشل في سجل العمليات لا يلغي حفظ الإعدادات أو الفاتورة.
- حفظ إعدادات المطعم يتعامل مع tax_rate/service_rate أو الأسماء القديمة tax_percent/service_percent، ويحدّث الاثنين إذا كانا موجودين.
- بيانات المطعم التي ترجع للواجهة توحّد أسماء نسب الضريبة والخدمة.
- تسجيل مطعم جديد يختار أعمدة restaurants الموجودة بدل افتراض أن المخطط مطابق تمامًا.
- جدول closings يتم إنشاؤه عند الحاجة إذا كان غير موجود؛ ولا يتم حذف جدول daily_closings القديم أو تعديل بياناته.
- كلمة المرور تستخدم PBKDF2 بعدد 100000 دورة المتوافق مع بيئة Cloudflare Workers.

الفحوصات التي أُجريت هنا:
- فحص صياغة JavaScript لملف worker.js بواسطة Node.js.
- فحص صياغة JavaScript المضمن في public/index.html.

لم يتم تنفيذ اختبار اتصال حي بقاعدة Cloudflare D1 من داخل بيئة البناء؛ لذلك يجب تجربة حفظ الإعدادات، ثم إنشاء صنف وفاتورة ومصروف وإغلاق يوم بعد النشر.
